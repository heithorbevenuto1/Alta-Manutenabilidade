Exemplo em Python • BAIXO ACOPLAMENTO • ALTA COESÃO

📄 Código "Limpo e Mantenível" ✅ BOM 

from abc import ABC, abstractmethod

# ==========================================
# 1. REGRAS DE NEGÓCIO ISOLADAS
# ==========================================

def calcular_salario_base(horas, valor_hora):
    """Calcula o salário base sem regras especiais"""
    return horas * valor_hora


def calcular_bonus_vendedor(total_vendas):
    """Regra de bônus do vendedor - função pura"""
    if total_vendas > 10000:
        return total_vendas * 0.10
    elif total_vendas > 5000:
        return total_vendas * 0.05
    return 0


def calcular_desconto_estagiario(salario_base):
    """Regra específica para estagiários"""
    return salario_base * 0.9


# ==========================================
# 2. ESTRATÉGIA POR CARGO (Polimorfismo)
# ==========================================

class CalculadoraSalario(ABC):
    """Classe base abstrata para todos os cargos"""
    
    @abstractmethod
    def calcular(self, horas, valor_hora, vendas=0):
        pass


class CalculadoraVendedor(CalculadoraSalario):
    def calcular(self, horas, valor_hora, vendas=0):
        base = calcular_salario_base(horas, valor_hora)
        bonus = calcular_bonus_vendedor(vendas)
        return base + bonus


class CalculadoraGerente(CalculadoraSalario):
    def calcular(self, horas, valor_hora, vendas=0):
        base = calcular_salario_base(horas, valor_hora)
        if horas > 160:
            return base * 1.2 + 500
        return base + 500


class CalculadoraEstagiario(CalculadoraSalario):
    def calcular(self, horas, valor_hora, vendas=0):
        base = calcular_salario_base(horas, valor_hora)
        salario = calcular_desconto_estagiario(base)
        if vendas > 3000:
            salario += vendas * 0.02
        return salario


class CalculadoraPadrao(CalculadoraSalario):
    def calcular(self, horas, valor_hora, vendas=0):
        return calcular_salario_base(horas, valor_hora)


# ==========================================
# 3. FÁBRICA DE CALCULADORAS
# ==========================================

def criar_calculadora(cargo):
    """Retorna a calculadora correta para cada cargo"""
    calculadoras = {
        "vendedor": CalculadoraVendedor(),
        "gerente": CalculadoraGerente(),
        "estagiario": CalculadoraEstagiario(),
    }
    return calculadoras.get(cargo, CalculadoraPadrao())


# ==========================================
# 4. FUNÇÃO PRINCIPAL - LIMPA E ORGANIZADA
# ==========================================

def calcular_salario(nome, cargo, horas, valor_hora, vendas=0):
    calculadora = criar_calculadora(cargo)
    salario_final = calculadora.calcular(horas, valor_hora, vendas)
    print(f"{nome} recebe: R$ {salario_final:.2f}")
    return salario_final

🟢 BOAS PRÁTICAS APLICADAS

  • Alta Coesão: Cada classe/função tem UMA responsabilidade bem definida
  • Baixo Acoplamento: As classes são independentes e podem ser alteradas isoladamente
  • Open/Closed: Aberto para extensão (novos cargos), fechado para modificação (não mexe no existente)
  • Polimorfismo: Cada cargo tem sua própria calculadora
  • Fácil Testabilidade: Cada regra pode ser testada isoladamente

🔧 Extensão: Adicionar "Analista" ✨ SEM QUEBRAR NADA

Veja como é simples adicionar um novo cargo. Basta criar uma nova classe e registrar na fábrica. 

# NOVA CLASSE PARA O CARGO "ANALISTA"
class CalculadoraAnalista(CalculadoraSalario):
    def calcular(self, horas, valor_hora, vendas=0):
        base = calcular_salario_base(horas, valor_hora)
        if vendas > 8000:
            return base * 1.15  # 15% de bônus
        return base

# REGISTRAR NA FÁBRICA (UMA ÚNICA LINHA)
def criar_calculadora(cargo):
    calculadoras = {
        "vendedor": CalculadoraVendedor(),
        "gerente": CalculadoraGerente(),
        "estagiario": CalculadoraEstagiario(),
        "analista": CalculadoraAnalista(),  # ⬅️ ÚNICA MUDANÇA!
    }
    return calculadoras.get(cargo, CalculadoraPadrao())

🎯 Princípio Open/Closed: O sistema está ABERTO para extensão (novas classes) e FECHADO para modificação (não mexemos nas classes existentes).

📊 Comparação: Ruim vs. Bom 📈 EVOLUÇÃO

❌ Código Ruim

  • Tudo na mesma função
  • 8 caminhos possíveis
  • Alto acoplamento
  • Difícil de testar
  • Risco ao mudar
  • Adicionar cargo: ~20min (arriscado)

✅ Código Bom (Mantenível)

  • Funções e classes isoladas
  • ~2 caminhos por método
  • Baixo acoplamento
  • Fácil de testar
  • Seguro para mudar
  • Adicionar cargo: ~3min (seguro)

💡 Conclusão: Investir em manutenibilidade desde o início economiza tempo, dinheiro e dor de cabeça. O código mantenível é mais caro para escrever HOJE, mas muito mais barato para manter AMANHÃ.
